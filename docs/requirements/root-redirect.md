# REQ-Root-Redirect：根路径 `/` 重定向到 `/webchat`

## 背景与目标

- 背景：自测阶段朋友通过隧道/浏览器直接访问根地址 `https://域名/` 时，Express
  默认返回 "Cannot GET /"（浏览器表现为白屏/一行报错），多位试用者踩坑
  （2026-10-10 朋友实测反馈）。
- 目标：访问 `/` 自动 302 到 `/webchat`，任何人打开域名直达登录/聊天页。

## 范围

**做**：`GET /` → `302 /webchat`。
**不做**：不改 `/webchat` 本身；不做其他路径的友好化；不动鉴权（静态页本就不鉴权）。

## 功能需求

1. 浏览器/微信内打开 `https://域名/` 应直接跳到聊天页。

## 非功能需求

- 302（临时跳转）而非 301，保留日后更换落地页的空间。
- 不影响 `/health`、API、静态资源等任何现有路由。

## 数据模型 / API / 前端改动

无数据模型与前端改动；仅新增一个 Express 路由。

## 验收标准

- [x] `curl -I /` 返回 302，Location 指向 `/webchat`
- [x] `/health`、各 API、静态页行为不变（npm test 全绿）
- [x] `npm run typecheck` 通过

## 审计要点

- 路由须注册在渠道 mount 之后、错误中间件之前，避免遮蔽任何现有路由
- 不得引入鉴权绕行：跳转目标 `/webchat` 的静态页本就公开
